# Full-screen images in the chat — implementation notes

> Agent-facing reference for [`docs/features/chat-image-zoom.md`](../../features/chat-image-zoom.md). The human-facing surface lives in that file; the implementation details, wire shapes, and source paths live here.

## Implementation notes

- The wrapper is `zoomableImage(img, label, opts)` in [frontend/src/components/chat/toolRender.js](../../../frontend/src/components/chat/toolRender.js). It puts the image inside a `<button>` whose click calls `openImageLightbox(src, alt)`. The lightbox itself (`openImageLightbox` / `teardownImageLightbox`) is unchanged and shared with the tool-card path — see [docs/agent/features/read-file-images.md](./read-file-images.md) for its DOM, its three close affordances, the `mouaif:teardown-lightbox` window event, and the 220 px / `position: fixed` mobile rules.
- `opts` was added so a caller can keep its own layout: `buttonClass` overrides the tool-card button class, `imgClass` overrides the classes forced onto the image, and `imgClass: null` leaves the caller's own class untouched (the wrapper then only adds `tool-card__image--zoomable`). Tool-card callers pass nothing and get the old behavior.
- Transcript surfaces in [frontend/src/components/chat/transcript.js](../../../frontend/src/components/chat/transcript.js):
  - `renderImageAttachments` wraps each user-turn attachment with `chat-msg__attachment-button` and `imgClass: 'chat-msg__attachment-img'`, so the message grid layout is byte-identical.
  - `makeMarkdownImagesZoomable(container)` walks `renderMarkdown` output (the final assistant answer and, when final, the reasoning body) for bare `<img>` nodes and swaps in a `chat-msg__image-button` wrapper. The system-prompt row is plain `<pre>` text (`buildSystemPromptRow`), so it has no markdown images and is not touched. It captures the node's slot (`parentNode` + `nextSibling`) before wrapping, because `zoomableImage` re-parents the image into the button and a naive `img.replaceWith(button)` would then be a no-op — the image is no longer a child of `container`. Already-wrapped images (`img.closest('.chat-msg__image-button')` / `.tool-card__image-button`) are skipped, so a re-render never nests wrappers; that closest-check is also the reason the function needs a real DOM (`container.querySelectorAll`) and bails out when the stub lacks one.
- CSS: [frontend/src/chat-transcript.css](../../../frontend/src/chat-transcript.css) adds `.chat-msg__attachment-button` and `.chat-msg__image-button` — bare block buttons, `padding: 0`, `border: 0`, `background: none`, `cursor: zoom-in`, `min-height: var(--tap)` so the tap target is ≥ 44 px. `.chat-msg__attachment-img` keeps its 140 px cap; a markdown image keeps the `.chat-msg__body img` rule (`max-width: 100%`).
- No new endpoint. The bytes are already in the transcript (markdown `src`) or the attachment record (`dataUrl`). Tool-card images, MCP image blocks and web-preview captures were already tappable; this closes the three transcript surfaces that painted bare `<img>` nodes.
- User-attachment thumbnails are read-only here, unlike the composer chip: tapping the bubble image opens the viewer, it does not open the Draft Craft annotator (that stays on the composer chip).
- Tests: [scripts/test-chat-image-zoom.js](../../../scripts/test-chat-image-zoom.js) loads transcript.js in a VM DOM stub and checks the wrapper nodes for each surface (attachment wrap, markdown wrap, reasoning wrap, no double-wrap on re-render). `scripts/test-read-image-preview.js` still covers the shared lightbox. Both are wired into the `test` and `lint` npm scripts.
