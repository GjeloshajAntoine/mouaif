# Grouped CLI tool — implementation notes

> Agent-facing reference for [`docs/features/grouped-cli-tool.md`](../../features/grouped-cli-tool.md). The user-facing surface lives in that file; the implementation details, wire shapes, and source paths live here.

## Public surface

[src/tools/groupCli.js](../../../src/tools/groupCli.js) exports:

| Export | Meaning |
| --- | --- |
| `SPEC` | The OpenAI-compatible function spec (`commands` required, 1–50 entries). |
| `TOOL_NAME` | `'group_cli'`. |
| `runGroupCli(opts)` | The runner: `{ projectDir, args, toolTimeoutMs, signal, onOutput, onBackgroundExit }` → `{ results, succeededCount, failedCount, runningCount, stillRunning, logs, durationMs }`. Throws `EBADINPUT` / `ETOOL_CAP` / the sandbox's error codes. |
| `formatGroupCliResult(out)` | The model-facing text (one numbered block per entry, then the tally). |
| `MAX_BATCH_ENTRIES` | Re-exported from `src/tools/files.js`: the one clustered-tool cap. |
| `DEFAULT_TOTAL_BUDGET_MS` | 5 min — the synchronous batch budget when the authorization gate returns none. |
| `BACKGROUND_LOG_DIR` / `BACKGROUND_LOG_MAX_BYTES` | `.mouaif/logs` / 4 MB. |
| `_backgroundChildren` | Test-only view of the live detached children. |

## Implementation notes

- **One runner, shared with `shell`.** [src/tools/shell.js](../../../src/tools/shell.js) now exports `resolveShellPlan(cmd, shellOverride)` — the argv/flag/quoting/interpreter-override resolution that used to be inlined in `runShell` — plus `registerLiveChild(child)` / `clearLiveChild(child)` over its `liveChildren` reap-on-exit set. `runShell` uses the plan; every synchronous batch entry calls `runShell`, so an entry's cwd, env denylist, `windowsVerbatimArguments` handling and per-stream truncation are identical to a single `shell` call. A background entry cannot use `runShell` (it must not be awaited), so it spawns through the same plan and registers itself with `registerLiveChild` — one live set, one exit hook, no leaked processes on shutdown.
- **`osLabel`, `shellExeDescription` and `resolveShellPlan` were added to shell.js's exports** so the batch spec can name the same OS/dialect wording the shell spec uses without duplicating the platform logic.
- **Background logging.** `ensureLogDir(root)` makes `<project>/.mouaif/logs`; `logFileName(cmd, startedAt)` produces `<startedAt>-<seq>-<slug>.log`, where `seq` is a per-process counter so two batches in the same millisecond cannot collide. `beginBackgroundLog(dir, fileName)` opens the file and returns `{ write, close }`; the file name is computed once by the caller and the *same* string is both announced in the result (`relPath`) and opened — computing it twice produced a result that named one file while the handle appended to another. Output is decoded with a `StringDecoder` per stream, capped at `BACKGROUND_LOG_MAX_BYTES`, and closed with `\n[mouaif] exit <code> after <ms>\n`.
- **Detach check.** `startBackgroundCommand` awaits `setTimeout(0)` (plus the child's own `error`/`exitCode`/`signalCode`) before reporting `status: 'running'`. A spawn that fails immediately (a missing shell) otherwise reported `ok: true` for a process that never existed; the check turns it into `{ ok: false, async: true, error: { code: 'ESPAWN' } }`. A long-lived `finished` promise settles the log, records the exit code and fires `onBackgroundExit`; its rejection is swallowed because nothing else awaits it.
- **Budget semantics.** The budget is checked *before* each synchronous entry starts, and the entry's own timeout is `min(entry.timeoutMs ?? DEFAULT_ENTRY_TIMEOUT_MS, budget)`. An entry that is skipped gets `ETIMEDOUT` data naming the budget and the time spent — never a silent drop — and `async` entries are exempt because they do not block the call.
- **Dispatcher.** [src/ai-stream.js](../../../src/ai-stream.js) resolves `workingDir` through `chatWorkingFolder.resolveForCall` for `shell`, `group_cli` and the file tools, then runs the batch with `toolTimeoutMs` from the authorization gate (never the model's raw value). Output chunks are re-emitted as `shell_output` frames carrying `index` / `label` / `cmd`, and (inside a delegated run) as `subagent_event` with `kind: 'shell_output'`, exactly like the `shell` path.
- **Approval summary.** The `group_cli` branch in `runSingleToolCall` builds a numbered, multi-line summary from `args.commands`, appending `[background]` for detached entries. The authorization module's `allowlist` branch (`src/tools/authorization.js`, `authorize`) gained a third `batchKey`: `group_cli` → `commands`, and the per-item target is `item.cmd || item.command`, so every command in the batch must match a pattern.
- **Catalog row.** `pushNativeTool(tools, { load: './tools/groupCli.js', name: 'group_cli', source: 'mouaif', … })` in [src/server-handlers-tools.js](../../../src/server-handlers-tools.js). The row's `source` must be the family key the trees render, so it is `mouaif` even though the tool itself lives in `src/tools/`.
- **Prompt presets.** `PRESET_TOOL_NAMES` in [src/prompts.js](../../../src/prompts.js) lists `group_cli` by name (it is a family leaf but not an app-store function), and [frontend/src/components/settings/presetTools.js](../../../frontend/src/components/settings/presetTools.js) adds it to `PRESET_DEFAULT_OFF_TOOLS` so a fresh preset baseline leaves the grouped tools unchecked.
- **Card.** `renderGroupCliToolResult` in [frontend/src/components/chat/toolRender.js](../../../frontend/src/components/chat/toolRender.js) renders one `.tool-preview__batch-entry` per command (status line + terminal output, a hairline between entries). `formatToolArgs` / `formatToolArgsFull` (frontend/src/components/chat/tools.js) join the entries with `›` for the collapsed head and number them for the expanded arguments block; `formatResultSummary` returns `N ok · N failed · N running · Nms`. `TOOL_VERBS.group_cli = 'Ran group'`.- **Live preview plumbing.** The call card for `group_cli` builds the same `.tool-card__shell-live-pre` body as `shell` (transcript.js `appendToolCallCard`), and the reconnect hint selector in frontend/src/components/chat/stream.js covers both names. `handleShellOutputEvent` and `bufferPendingShellOutput` needed no change: they key off the call id.
- **Tests.** [scripts/test-group-cli.js](../../../scripts/test-group-cli.js) covers the spec/catalog, entry validation, ordering, a batch that continues past a failure, per-entry timeouts, the budget, async detach + log contents, authorization (family off / leaf off / family allow / every-command allowlist), a real multi-turn `streamChat` round against an SSE fixture (including the `off` advertisement gate), the tool-group model + generated mirror + preset baseline, and the card renderer. [scripts/test-grouped-file-tools.js](../../../scripts/test-grouped-file-tools.js) and [scripts/test-shell-tool.js](../../../scripts/test-shell-tool.js) guard the refactored shared runner.
