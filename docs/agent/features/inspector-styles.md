# Inspector Styles panel — implementation notes

> Agent-facing reference for [`docs/features/inspector-styles.md`](../../features/inspector-styles.md). The human-facing surface lives in that file; the implementation details, wire shapes, and source paths live here.

## Implementation notes

- **Computed filtering is a pure module.** `computedFilter.js` owns selecting rows (the search predicate, the all/declared/changed semantics, the render cap, the empty-state copy, and the one-line status sentence) while `stylesOrder.js` owns ordering them (changed-first hoisting); the panel composes the two, so the order is applied first and the filter narrows the result — the visible list still leads with what the user just changed. The `set` filter is fed from the element's own inline property names, which is why it and the Declared list can never disagree about what the element declares. `statusLine` is pure too, so the wording is asserted without a render. The **Show** label and the chips it labels are one element (`inspector__computed-showgroup`), not two siblings: pinned right on its own, the label stayed on the first row while the chips wrapped below it, leaving "SHOW" floating at the right edge at 360 px.
- **Declaration validation is a pure module.** [`frontend/src/components/inspector/declaration.js`](../../../frontend/src/components/inspector/declaration.js) owns `normalizeProp` (case-insensitive names, case-*sensitive* custom properties), `validateDeclaration` (the pre-write check the sheet runs on every keystroke) and `declarationApplied` (the post-write verdict). The `supports` predicate is injected rather than read from the global `CSS`, so the rules are unit-testable with no browser. The sheet and the write path deliberately use the *same* function, so the inline hint and the error raised by Apply cannot disagree. The read-back lives in [`frontend/src/components/inspector/events.js`](../../../frontend/src/components/inspector/events.js) `setInlineStyleProperty`, which returns `{ applied, read }` from the in-page function and throws when `applied === false`; a target that returns no verdict is left to stand, since the write was issued and nothing contradicts it.
- **The zoom preference is versioned, and the auto-fit heuristic is not persisted.** `PreviewPanel` stores an explicit toggle under `mouaif:inspector:previewZoom2`. The v1 key was also written by the auto-fit path, and while the Touch stylesheet was collapsing the preview frame (see [Inspector touch controls](../../features/inspector-touch-controls.md)) auto-fit saw a permanently "too wide" frame and wrote `size` on every connect — a derived value that was indistinguishable from a real preference and left the preview stuck in panned natural-size mode. v1 is now read once and dropped. Auto-fit itself is recomputed per frame width and never stored, because it is a rendered-mode decision, not a choice.
- **Files:** [`frontend/src/components/inspector/StylesPanel.jsx`](../../../frontend/src/components/inspector/StylesPanel.jsx) (panel + edit sheet + pinned live preview + matched rules), [`frontend/src/components/inspector/liveShot.js`](../../../frontend/src/components/inspector/liveShot.js) (the pinned preview's re-capture pacing, a pure module with injected timers so it is unit-testable), [`frontend/src/components/inspector/pinnedStack.js`](../../../frontend/src/components/inspector/pinnedStack.js) (the pinned identity row's measured height, published as the custom property the group chip row pins against — a pure module with an injected observer so it is unit-testable), [`frontend/src/components/inspector/declaration.js`](../../../frontend/src/components/inspector/declaration.js) (declaration validation, a pure module), [`frontend/src/components/inspector/stylesOrder.js`](../../../frontend/src/components/inspector/stylesOrder.js) (changed-first ordering, a pure module so it is unit-testable), [`frontend/src/components/inspector/matchedRules.js`](../../../frontend/src/components/inspector/matchedRules.js) (matched-rule normalization, also pure), [`frontend/src/components/inspector/computedFilter.js`](../../../frontend/src/components/inspector/computedFilter.js) (computed search/filter/paging, also pure), [`frontend/src/components/inspector/events.js`](../../../frontend/src/components/inspector/events.js) (CDP helpers), [`frontend/src/components/Inspector.jsx`](../../../frontend/src/components/Inspector.jsx) (panel wiring + preview tap routing), [`frontend/src/inspector.css`](../../../frontend/src/inspector.css) (the `@import` entry for the thirteen per-panel Inspector stylesheets).
- **CDP surface:** the helpers reuse the existing CDP proxy with no new server endpoints. `buildNodeModel` calls `DOM.describeNode`, `DOM.resolveNode`, `CSS.getComputedStyleForNode`, `DOM.getBoxModel`, and `Overlay.highlightNode`; `pickNodeAt` adds `DOM.getNodeForLocation`; `selectBySelector` adds `DOM.getDocument` + `DOM.querySelector`; edits use `Runtime.callFunctionOn` (`style.setProperty` / `style.removeProperty`). `captureElementShot` uses `Runtime.callFunctionOn` to centre + measure the element, then `Page.captureScreenshot` with a `clip`; `captureElementShot(objectId, { scroll: false })` is the live variant — it measures without centring and refuses outright (`null`, before any CDP call) when `captureBeyondViewport` is off, because a viewport-only target cannot capture a region faithfully. Both capture paths go through `runCapture`, which serializes them on one queue and restores the wanted viewport (`Emulation.setDeviceMetricsOverride`, or `clearDeviceMetricsOverride` for the native **Auto** preset) after any capture that carried a `clip`. `readElementStyles` is the post-edit read: one `Runtime.callFunctionOn` returning `{ inline, computed }` keyed by property name. `readElementTree`, `selectAncestorNode`, and `selectChildNode` are three more `Runtime.callFunctionOn` calls — one `returnByValue` read of the ancestors/children labels, and two that resolve a neighbouring element to an `objectId` — so tree navigation needs no nodeId and no selector re-query. `requestNodeId` was extracted from `buildNodeModel` so the highlight and any future CSS-domain read share one "resolve a nodeId, or 0" fallback.
- **Capture serialization:** picks, applies, and manual refreshes can overlap, so `StylesPanel` keeps a `shotSerial` counter — only the newest capture may write to state, and a slow capture for a previously selected element can never replace the current element's preview. The live loop deliberately takes no serial: it must not cancel a capture the user asked for, so it drops its own result instead when a manual capture starts (or the selection moves) mid-flight. `lastShotData` is the byte-comparison cache behind the unchanged-frame drop, and it is cleared whenever the selected element changes — otherwise two identical elements (a repeated card) would have the second one's first capture dropped as "unchanged". Underneath all of it, every `Page.captureScreenshot` on the connection is serialized by `queueCapture` in `events.js`, which is what keeps the two panels' loops from corrupting each other's frames.
- **Pick-mode tap routing:** `PreviewPanel` passes every tap to a wrapper that checks the parent's `stylesActive` flag. When on, the tap's screenshot coordinates go to the Styles panel's `pickFromPoint`; otherwise they fall through to `clickAt`. `viewportCoords` (extracted from `clickAt`) does the single screenshot→viewport coordinate mapping used by both paths.
- **Pick-mode feedback and auto-disarm:** the parent passes `pickMode`, `pickHint` and `onPickCancel` into `PreviewPanel`, which renders the banner over the screenshot (and in its full-screen overlay, since the panel stays mounted behind it) and marks the tap surface `is-picking`. The outcome of a pick is routed through `settlePick` in [`frontend/src/components/inspector/pickMode.js`](../../../frontend/src/components/inspector/pickMode.js): a selection disarms pick mode, a miss or a CDP error keeps it armed, and `pickFromPoint` reports the outcome by resolving to `true`/`false`. Without this the user could not tell whether a tap would select an element or poke the page, and the next tap after a successful pick silently selected something else instead of clicking.
- **Inspectable elements only:** picks resolve through the DOM domain, so text nodes and `::-webkit` pseudo parts are not selectable; tap the nearest real element.
