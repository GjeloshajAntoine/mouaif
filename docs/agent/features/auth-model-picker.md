# Per-run model choice on the subagent authorization card — implementation notes

> Agent-facing reference for [`docs/features/auth-model-picker.md`](../../features/auth-model-picker.md). The human-facing surface lives in that file; the implementation details, wire shapes, and source paths live here.

### REST

The existing decision endpoint is unchanged; `payload` is now also honored for `subagent` calls:

| Method | Path | Body | Response |
|--------|------|------|----------|
| `POST` | `/api/tools/authorization/decision` | `{ projectDir, chatId, callId, decision, payload?: { modelOverride: { providerId, modelId }, thinkingLevel?: string } }` | `{ ok: true }` |

`payload` was already a generic channel used by `ask_user`; `subagent` is the second consumer. A malformed override (missing `providerId`/`modelId`, unknown model, missing provider connection) fails the delegated call loudly with a typed `EUNKNOWN_MODEL` / `EPROVIDER_NOT_FOUND` tool error — never a silent fallback.

## Implementation notes

- **Payload channel.** `src/tools/authorization.js` `recordDecision` forwards any `payload` object through the pending decision's `resolve({ decision: 'allow', payload })`. `src/ai-stream.js` already captured that for `ask_user`; it now also captures `payload.modelOverride` and `payload.thinkingLevel` for `subagent` and passes them to the dispatcher as `callOpts.modelOverride` / `callOpts.thinkingLevel`.
- **Safe hydration.** The override record is resolved inside the subagent branch of `src/ai-stream.js`: the project model record (found by `modelId` + `providerId` in `settings.getResolved(...).models`) contributes only identity/selection metadata (`id`, `provider`, `label`, `contextWindow`, `thinking`, `pricing`); transport and credentials always come from the app-level provider connection — the same sanitization rule `resolveModel` enforces in `src/server-shared.js`. Live-catalog models that are not in the project `models` array resolve by provider id.
- **Card UI.** `buildAuthModelPicker(state, request, projectDir)` in [frontend/src/components/chat/cards.js](../../../frontend/src/components/chat/cards.js) builds the control from `state.models` + `state.liveByProvider` and renders [frontend/src/components/AuthModelPicker.jsx](../../../frontend/src/components/AuthModelPicker.jsx) into a host element. That adapter owns this imperative card's model + thinking selection and passes them to the props-driven `ModelPickerField` and `ThinkingSelectField`; the current selection is exposed via `host._selected()` (returning `{ modelOverride, thinkingLevel }`) so the decision payload reads it. `authorizationCard` gained a trailing `state` argument; all call sites in [frontend/src/components/chat/stream.js](../../../frontend/src/components/chat/stream.js) — the direct `/shell` path, the pending-reload path, and both SSE paths (top-level and nested subagent) — pass it through.
- **Bookmarks (pinned / recent).** `AuthModelPicker` owns bookmark state with the same helpers the chat top bar uses ([frontend/src/components/chat/modelPicker.js](../../../frontend/src/components/chat/modelPicker.js) `loadPinned` / `loadRecent` / `loadRecentFromServer` / `touchRecent` / `togglePin`). It builds a minimal `{ props: { projectDir }, recentModels: [] }` bag from the `projectDir` argument (pins key off `projectDir` in localStorage; recent is server-backed). It passes `pinned`, `recent`, and `onTogglePin` to `ModelPickerField`, and supplies it as `onOpen` to `loadRecentFromServer(bookmarks)` so the Recent section refreshes each time the sheet opens — matching the chat top bar's behavior. Picking a model on the card also calls `touchRecent`, and pinning toggles via `togglePin` (which drops a freshly pinned model from Recent to avoid duplication).
- Styling lives in [frontend/src/chat-view.css](../../../frontend/src/chat-view.css) under `.mp*` (the shared field) and [frontend/src/tool-cards.css](../../../frontend/src/tool-cards.css) under `.tool-card__auth-model-*` (the card slot, full-width, ≥ 44 px tap target). The card renders `variant="sheet"`, so at phone widths it opens the same fixed visual-viewport modal as the chat top bar rather than an anchored popover clipped by the transcript.
