# PWA — install, offline shell, update prompts — implementation notes

> Agent-facing reference for [`docs/features/pwa.md`](../../features/pwa.md). The human-facing surface lives in that file; the implementation details, wire shapes, and source paths live here.

## Implementation notes

- **Build pipeline.** `frontend/public/manifest.webmanifest` and `frontend/public/icons/*.png` are static; Vite's default `publicDir` copies them into `dist/` at build time, and `base: '/'` in `frontend/vite.config.js` keeps every emitted URL at the root. `frontend/build/sw-src.js` is the SW source — a small Vite plugin in `frontend/vite.config.js` reads it on `generateBundle`, replaces `__CACHE_VERSION__` with the first 8 hex chars of `sha256(sw body)`, and emits `dist/sw.js`.
- **Server.** `src/server-web-static.js` serves the built `frontend/dist/` at the root (falling back to the pre-build `frontend/` for development). `applyPwaHeaders()` sets:
  - `Service-Worker-Allowed: /` and `Cache-Control: no-cache` on `/sw.js`,
  - `Cache-Control: public, max-age=31536000, immutable` on fingerprinted `.js`, `.css`, `.png`, `.webp`, `.svg`, `.ico`,
  - `Cache-Control: public, max-age=300` on `manifest.webmanifest`.
  The `/favicon.ico` endpoint serves the real `icons/favicon-32.png`. A legacy `/web/` route 301-redirects to `/` so old bookmarks keep resolving (the hash fragment survives the redirect).
- **Client side.** `frontend/src/sw-registration.js` only registers `/sw.js` with `scope: '/'` (no-op in dev) and owns the waiting-worker update signal. `frontend/src/pwa-connectivity.js` tracks `navigator.onLine` plus same-origin app-shell fetch failures. `frontend/src/push-page-bridge.js` answers fresh notification visibility queries, while `frontend/src/notification-click.js` owns notification navigation and the iOS IndexedDB cold-launch handoff. `frontend/src/components/PwaBanners.jsx` renders the offline + update banners.
- **Update semantics.** A first install posts `SKIP_WAITING` immediately because no previous bundle is active. Subsequent workers stay waiting until the user taps **Reload**. The page then posts `SKIP_WAITING`; activation runs `clients.claim()`, `controllerchange` fires, and the page reloads once. This prevents an update from taking over beneath an old JavaScript bundle.
- **Lint.** `npm run lint` runs `node -c` on every `.js` file in `bin/`, `src/`, and `frontend/build/`. Three new scripts (`generate-icons.js`, `sw-src.js`, `check-icons.js`) plus `vite.config.js` are wired into the lint chain.
- **Tests.** `scripts/test-pwa.js` stands up an in-process server on an ephemeral port and asserts: `<link rel="manifest">` and `<link rel="apple-touch-icon">` in `/`, manifest JSON shape (`id`/`start_url`/`scope` all `/`), theme color + icons, SW JS body + `Service-Worker-Allowed: /` + `no-cache` + `install`/`activate`/`fetch` handlers + `/api/` bypass, every icon reachable as `image/png` with the PNG magic intact, favicon now returns 200, and the hashed CSS asset carries `immutable`. `scripts/test-index-first-paint.mjs` covers the pre-stylesheet frame: `frontend/index.html` must carry an inline `html { background: ... }` rule in `<head>` ahead of the bundler-injected stylesheet link. The document has no background of its own otherwise, so between the commit and the arrival of the bundle's CSS the browser paints its default canvas — `#121212` with the `color-scheme: dark` meta, `#fff` without it, measured at 390 × 844 — i.e. a lighter full-screen frame on every reload ("grey flashes with page reload"). The test pins three facts: the rule lives in `<head>`, it precedes the bundle's stylesheet, and its background stack equals the bundle's `html` background with `var(--bg)` resolved to its literal. Matching the values is what stops the second symptom — the visible background step on reload. An earlier inline rule set only the solid base colour, which avoided the flash but let the bundle's `radial-gradient(...), var(--bg)` repaint visibly once the CSS landed; pinning the full stack ends both. A warm profile hides the bug because the service worker precaches `index.html` and serves the CSS cache-first; a first visit, a cache-disabled hard reload, or a fresh profile shows it.
