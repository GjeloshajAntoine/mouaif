# Web preview tool (`webpreview`) — implementation notes

> Agent-facing reference for [`docs/features/webpreview.md`](../../features/webpreview.md).

## Implementation notes

- Server runner: [`src/tools/webpreview.js`](../../../src/tools/webpreview.js) opens a fresh debug-Chrome target for every call, captures one JPEG, and closes the target. Repeating a call is the reload mechanism.
- AI wiring: [`src/ai-stream.js`](../../../src/ai-stream.js) advertises and dispatches the tool. It emits the rich screenshot result to the frontend but suppresses `webpreview` image parts from the follow-up model conversation.
- State bridge: [`frontend/src/components/chat/webpreviewState.js`](../../../frontend/src/components/chat/webpreviewState.js) keeps the latest capture and notifies the mounted chat view.
- Dock: [`frontend/src/components/chat/WebpreviewDock.jsx`](../../../frontend/src/components/chat/WebpreviewDock.jsx) renders the compact user-only image between the transcript and composer. The card is `width: min(26%, 6.5rem)` right-aligned, and because it is a flex item in the chat column its height comes out of the transcript — so the image is height-capped (`max-height: min(24dvh, 11rem)` with `object-fit: cover; object-position: top` in [`frontend/src/chat-composer.css`](../../../frontend/src/chat-composer.css)); a 375 × 812 capture is 94 × 176 on a 360 px-wide phone instead of ~200 px tall. Cap the **image**, not the card: a `max-height` on the card leaves the image overflowing it, because a percentage height cannot resolve against an auto-height parent. The dismiss button is the 22 px circle on the card's top-right border (visual size; it has no expanded hit area, and a 44 px one would cover the card's own tap-to-open region — see `docs/agent/features/modal-sheets.md` for the `.tap-target` helper and when it is unsafe).
- Viewer: [`frontend/src/components/chat/WebpreviewModal.jsx`](../../../frontend/src/components/chat/WebpreviewModal.jsx) opens only after a user taps the dock and shows the complete image.
- Viewer header at ≤ 430 px: **one row**, no wrapping. `.wp__head` is `flex-wrap: nowrap` with `align-items: center`; `.wp__head-text` is the only flexing child (`flex: 1 1 auto; min-width: 0`) so it ellipsizes and every control keeps its intrinsic width. The Refresh label is hidden at this width (`display: none` on its `span`) to buy the title room — which makes it the only control in the row whose contents are a bare glyph, and therefore the only one whose centring is visible. `.wp__action` is **not** a `.btn`, so it carries its own `justify-content: center`: without it the 14 px glyph sat at `padding-left: 4px` — 5 px from the button's left edge and 25 px from the right, visibly off-centre in a 44 × 44 px square. Measured in Chrome at 320/340/360/375/390/414/430 px: the inset is now 15/15 on every width, the head stays 55 px on one row, and the button's centre still resolves to the button. The Inspector's mirrored `.inspector__preview-fs-refresh` declares the same centring in its own rule rather than inheriting it from `.btn`, so neither header depends on the other's file. `.wp__size-select` is capped at the `7.5rem` basis the base rule already gives it — the longest option ("Laptop · 1280×800") needs 110 px, so a smaller cap clips the native select's label. `.wp__close` is `position: static` here: it is only absolutely positioned in the *wrapped* layout, so returning it to the flow is what keeps it at the end of the row without any inset arithmetic. Do **not** reintroduce `top: calc(var(--safe-top) + 8px)` — the ✕'s containing block is the head, and the overlay in [`frontend/src/sheets.css`](../../../frontend/src/sheets.css) already applies `padding: var(--safe-top) 0 var(--safe-bottom)`, so the head starts below the status bar and re-adding the inset offsets it a second time (47 px on a notched phone), landing its transparent 44 px square on the controls. Measured at 320/340/360/390/414/430 px: one row, head 55 px (was 107 px when it wrapped), all four controls 44 px tall, 8 px gaps, no overflow; at 320 px the title still shows ~10 characters. Later tightened to **49 px**: head padding `2px 6px` (was `5px 8px`), gaps 6 px (was 8 px), title `0.8rem` / subtitle `0.64rem` with `line-height: 1.2`. The 44 px controls now set the row height, so 49 px is the floor unless they go below `--tap` — don't shrink them. The CLI modal head (`.cli__head`, 47.5 → 37 px) and the file editor head (`.fe__head`, 79 → 69 px) got the same trim.
- The Inspector's own full-screen preview header (`.inspector__preview-fs-head` in [`frontend/src/inspector-pick-mode.css`](../../../frontend/src/inspector-pick-mode.css)) still wraps on narrow phones and was left as it is. It carries one extra control (a zoom toggle) on top of Refresh / Size / Close, so a single row would leave the title only ~28 px (~3 characters) at 320 px — worse than the 55 px it gives the viewer. Its wrapped layout keeps the `position: absolute` close button and therefore the `top: 8px` (not `calc(var(--safe-top) + 8px)`) offset. The two headers share their control styling but not their row model, so a change to one does not imply the other. Its Refresh button is the one thing they *do* share: it also collapses to a bare glyph at ≤ 430 px, so `.inspector__preview-fs-refresh` declares its own `justify-content: center` (15/15 glyph inset) instead of relying on the `.btn` class it happens to carry.
- Transcript: [`frontend/src/components/chat/transcript.js`](../../../frontend/src/components/chat/transcript.js) publishes successful results immediately because result bodies are lazy. The normal tool card remains collapsed and does not contain the image.
- Styling: [`frontend/src/chat-composer.css`](../../../frontend/src/chat-composer.css) contains both dock and full-viewer styles.

- The native runner in `src/tools/webpreview.js` opens a temporary debug-Chrome tab, waits for the page, applies the requested viewport (default 375 × 667 phone), captures a JPEG, and closes the tab. It accepts a `viewport` arg via the model spec, and `resolveViewport()` maps preset ids or `WIDTHxHEIGHT` strings (clamped) to a capture rectangle.
- `frontend/src/components/chat/webpreviewState.js` bridges imperative tool results to `WebpreviewDock.jsx`.
- The dock is rendered directly between `.chat-view__transcript` and `.chat-view__composer-row` in `frontend/src/components/chat/Chat.jsx`.
- The full-screen viewer (`WebpreviewModal.jsx`) shows the capture resolution in its footer meta and exposes a **Refresh** button plus a native **Size** selector. Its **Custom** option validates width and height before sending a `WIDTHxHEIGHT` viewport. These controls call `POST /api/tools/webpreview` (implemented in `src/server-handlers-tools.js`) to re-capture at a chosen size. That endpoint goes through the same `webpreview` authorization gate as the model path; `Chat.jsx` handles `EAUTH_REQUIRED` by mounting the shared authorization card and retrying with the original call ID after approval.
- Screenshot bytes are emitted in the rich UI result only. `src/ai-stream.js` does not append them as model image input; the model receives compact URL, title, size, dimension, and viewport metadata.
- Repeating the tool call opens a fresh temporary tab, so each call functions as a reload.
