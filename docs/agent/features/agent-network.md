# Agent network — implementation notes

- Model: `frontend/src/components/chat/agentNetwork.js` (pure, no DOM). Node ids are tool call ids; `ROOT` is the chat's own agent. `ingestMessages` folds persisted top-level `role: 'tool'` rows (and, recursively, each settled subagent's `result.chat`); `ingestStreamEvent` folds live frames and unwraps one `subagent_event` envelope per delegation level. Only the live path returns pulses.
- Store: `agentNetworkState.js` keeps one network per `projectDir::chatId`. Hooks: `renderTranscript` / `reconcileTranscript` (`syncAgentNetwork`), the owner SSE stream and the `@agent` NDJSON path in `stream.js`, the follower in `live.js` (`agentNetworkEvent`), and turn end in both (`agentNetworkTurnEnded`). A chat opens on its newest page only, so once per chat the store also fetches `GET /api/chats/:id/agent-rows?beforeSeq=<first loaded seq>` (`listAgentRows` in `src/chatdb.js`: subagent tool rows plus user rows reduced to `{ role, seq }`) and folds those rows in ahead of the loaded page; without it an idle chat whose delegations were older than the page showed no dock.
- `ingestMessages` runs on every reconcile, so rows are skipped by `phase:id` (`seenRows`): a settled subagent result can be large and must not be re-parsed each tick.
- Status only moves forward. `ended` is the soft exception: a turn that finished (or a later user row in the persisted transcript) ends what that turn left running, but a later `subagent_status` / `subagent_messages` report still overrides it. Turn boundaries come from row positions on each pass, so older history paged in later never ends the turn running now.
- Only a top-level background run (and what runs under it) outlives its turn; a background run started by a foreground subagent lives in that run's scope and ends with the turn. A run that settles also ends the children it left running (its child scope closes, `childScope.finish()`), including background children its nested chat never polled.
- A frame can name an agent before the frame that launched it (a page that joined mid-run, a `subagent_send` to a run on an older page). That agent becomes a `stub` under the agent whose `subagent_event` envelope carried the frame (envelopes are only wrapped by runs, so their `parentCallId` is always an agent); its `start` frame gives it its name, and its real launch then sets its parent and delegation time, never under its own descendant.
- Group members declared by `subagent_group_create` / `_status` are placeholder nodes (`member:<groupId>:<memberId>`) until a `subagent` call with that `groupId` + `memberId` arrives.
- Dock: `AgentNetworkDock.jsx` + `agent-network.css`, mounted in the bottom stack of `Chat.jsx` (after the web preview dock, before the composer row), not over the transcript. It is rendered with the `.tool-card` head/body classes so it matches every other chat element; the fullscreen glyph is the MCP App card's. Modes: `collapsed` / `expanded` (persisted in `localStorage` `mouaif.agentNetwork.expanded`) and `fullscreen` (not persisted; portaled to `<body>` so a transformed ancestor cannot trap the fixed overlay; `useModal` gives Escape, focus trap and focus restore). Pulses animate with `requestAnimationFrame` + `getPointAtLength` (SMIL `begin` is relative to document time and CSS `offset-path` on SVG is uneven across engines). Pulses only queue while the graph is shown; collapsed, the head's latest-message line slides in instead. Only messages pulse: a child streaming text or reasoning only moves `waiting` to `running` (the ring shows it working). Feed rows and the head line are keyed by the entry's `seq`, and only `live` entries newer than the feed seen when the dock mounted, expanded or switched chats get `is-arriving`.
- Replaced the per-card Mermaid schemas (`buildSubagentToolMermaid` / `buildSubagentRunMermaid`, removed from `mermaid.js`). Tests: `scripts/test-agent-network.mjs`.
- `layoutNetwork(net)` in `frontend/src/components/chat/agentNetwork.js` returns the top-down tree; `layoutNetwork(net, { vertical: true, width })` returns the outline. Both return `nodeW` and `vertical`, and `edgePath(a, b, kind, layout)` draws edges for either shape.
- `AgentNetworkDock.jsx` measures the graph container with a `ResizeObserver`. It uses the tree when `tree.width` fits (in full screen, when 80% of it fits, since full screen may shrink the tree that far), otherwise the outline.
- Message pulses between a parent and child travel the tree edge; between any other pair (group handoffs) they travel the dependency arc.
- Feed entries carry a `seq` that keeps growing past the 80-entry cap; the dock keys rows and the head line by it, and the **Messages** count is the total. Each entry keeps a one-line `text` (140 characters) and the whole message as `full` (up to 8,000), and a node keeps its `answer`.
- `latestTurnFailed(net)` drives the head's red state from `net.turnRoots`, the top-level delegations of the latest turn (from row positions, or the live turn before its rows are saved).
- **Show in chat** falls back to `jumpToToolCard(callId, flash)` from `useChatState.js`, which runs `jumpToSeq` from `jumpToRun.js` with a `find` for the run's top-level card.
- `scripts/test-agent-network.mjs` covers the outline's row order, indentation and width, the feed seq, full text, nested order, repeated polls, background answers and the latest-turn state; `scripts/test-jump-to-run.mjs` covers the custom finder.
