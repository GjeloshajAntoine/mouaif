Memory footprint and payload size

Overview

mouaif runs as a long-lived server, often on a small box or next to other dev tools, and its UI is usually opened on a phone over a mobile link. The server loads optional subsystems only when they are first used, keeps its in-memory tables bounded, and serves the web bundle compressed. The chat view defers the heavy overlays it rarely needs.

Usage

Nothing to configure. The effects are:

  • An idle mouaif serve starts with about 35% fewer loaded modules and a smaller resident set.

  • Browsers download the app shell and hashed assets brotli- or gzip-compressed, about 3–4× smaller over the wire.

  • Opening a chat no longer downloads the web-preview viewer or the Draft Craft image annotator until one of them is tapped.
